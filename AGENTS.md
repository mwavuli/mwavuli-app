# AGENTS.md

Operating guide for AI agents and contributors in this repository.

## `.scratch/`

`.scratch/` holds working files: do not read or search them unless explicitly
requested or genuinely required to proceed. They are version-controlled all the
same — stage and commit `.scratch/` like any other path (e.g. under "commit
all"); never add it to `.gitignore` or exclude it from a commit.

Nothing under `.scratch/` is authoritative. A decision belongs in `brand/` or
`business/`, or for infrastructure in `docs/design/`, where it can be found.

## Release phase

Pre-launch: no real user, no real data, no deployed site. The change that lets the first real user in
flips this to live.

## Brand

Site, web and mobile code use the brand and design language in `brand/`: colours,
fonts, radii and shadows come from the tokens through the theme in `packages/theme/`
(`theme.css` for the site and the web app, `native.cjs` for mobile), and logos and
icons from `brand/logo/` and `brand/icons/`, imported as `@mwavuli/brand`. The theme
resets Tailwind's default palette, so an off-brand utility such as `bg-blue-500`
generates nothing. Deviations follow `brand/09-governance.md`.

## Workspace

An Nx and pnpm monorepo: `api/`, `site/`, `web/`, `mobile/`, `infra/` and the shared
`packages/`. See `README.md`. Run everything through Nx, for example
`pnpm nx run-many -t lint typecheck test build check`.

- Boundaries rest on the tags each project declares (`nx` in its `package.json` or
  `project.json`) and the rules in `eslint.config.mjs`. A persona's portal
  (`web/tenant`, `mobile/ops`, and so on) may import shared packages only, and a shell
  reaches a portal only through the dynamic `import()` in its `registry.ts`. When an
  import is refused, move the shared code into a shared package; do not loosen the rule.
- Dependency versions are named once, in the catalogs in `pnpm-workspace.yaml`.
  Never add a `minimumReleaseAgeExclude` entry (pick an older version) or approve an
  install script (`allowBuilds`) without the owner.
- `mobile/*/ios` and `mobile/*/android` are generated by `expo prebuild`: never edit or
  commit them. Mobile builds and releases run locally through Fastlane, never in CI.
- Infrastructure is applied by a person. CI only validates it, and no agent runs
  `terragrunt apply` or uses the shell's default AWS credentials for it.
